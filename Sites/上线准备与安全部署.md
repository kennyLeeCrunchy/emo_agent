# Emo Agent：ChatGPT Sites 上线准备与安全部署

## 结论与身份模型

公开试玩采用“Sites 托管前端与服务端代理，本机运行模型”的结构。电脑、FastAPI、Cloudflare Tunnel 任一停止，推理功能都会离线。

- 未登录访客：Sites 服务端生成随机 ID，写入 `HttpOnly + Secure + SameSite=Lax` Cookie。同一浏览器配置通常保持同一 ID；换设备、无痕窗口或清除 Cookie 会获得新 ID。
- 已登录访客：Sites 服务端使用 `oai-authenticated-user-email` 建立稳定身份。本机后端只保存经 HMAC 派生的不可逆标识，不保存邮箱。
- 浏览器提交的 `user_id`、`X-User-Id` 或身份头一律不作为公开模式下的授权依据。

官方 Sites 文档要求身份与授权决定留在服务端；公开 Site 可同时允许未登录访问与可选的 Sign in with ChatGPT。

## 架构和信任边界

```text
浏览器
  -> ChatGPT Site（同源页面）
  -> Sites 服务端 API 代理
       - 生成/读取访客身份
       - 注入共享代理密钥
       - 限流与固定上游地址
  -> Cloudflare Access（服务令牌校验）
  -> Cloudflare Tunnel（仅出站连接，不做路由器端口映射）
  -> 127.0.0.1:7860 FastAPI
  -> 本地 Whisper / RoBERTa / SQLite / 外部模型 API
```

`EMO_AGENT_PROXY_SECRET` 只存在于 Sites hosted secrets 与本机进程环境中。Cloudflare Access 服务令牌也只存在于 Sites hosted secrets。即使隧道 URL 被发现，也必须同时通过 Cloudflare Access 和应用代理密钥校验。

## 已写入代码的安全控制

- `EMO_AGENT_PUBLIC_MODE=true` 时，除健康检查外的 `/api/*` 必须携带正确的 `X-Emo-Proxy-Secret`。
- 公开模式忽略客户端声明的用户 ID，只信任代理注入的 `X-Emo-User-Id`，并在落库前再次做 HMAC 派生。
- 音频默认最大 20 MiB，并限制允许的 MIME 类型。
- 普通接口与高成本推理接口分别限流；音频分析默认仅允许一个并发任务。
- 启用 DeepSeek 后，普通 LLM 请求先按最多两次工具循环预留额度；原生联网搜索按 4 个额度预留。全站默认每天最多 100、每位访客默认每天最多 20 个额度，计数保存在本机 SQLite，重启不会清零。
- 单条用户输入默认最多 2,000 字符；普通回复最多 1,000 tokens，摘要最多 1,500 tokens，单个工具结果最多 3,000 字符。上下文使用 64K token 硬上限、48K 压缩触发线和 32K 压缩目标，并保留最近最多 20 条原文。
- 会话摘要失败时每隔 30 秒重试，单个失败周期总共尝试 3 次；仍失败则返回 503 并进入 10 分钟冷却。代理超时为 210 秒，以覆盖三次上游尝试和两段等待。
- 会话读取、删除、记忆读取和删除都绑定服务端解析出的用户身份。
- API 响应增加 `nosniff`、`no-referrer`、权限策略与禁止缓存头。
- 公开模式不向访客返回内部推理异常细节。
- 启动脚本强制监听 `127.0.0.1`，并拒绝缺少强代理密钥的公开启动。
- `Sites/hosted-site` 是可发布的 Vinext 项目；同源 `/api/*` 代理会剥离浏览器伪造的身份和密钥头，再注入可信身份与服务端密钥。

这些是应用层防护，不替代操作系统更新、低权限账户、磁盘加密、备份和日志巡检。

## 一次性准备

1. 安装并登录 `cloudflared`，创建命名 Tunnel 和专用子域名。
2. 将 `Sites/cloudflared-config.example.yml` 复制到仓库外，填入 Tunnel UUID、证书路径和域名。
3. 将 `Sites/.env.example` 复制为 `Sites/.env.local`。该文件已被项目的 `.gitignore` 中 `.env.*` 规则排除。
4. 生成至少 32 字节随机密钥，例如在 PowerShell 中执行：

   ```powershell
   $bytes = New-Object byte[] 32
   [Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
   [Convert]::ToHexString($bytes).ToLowerInvariant()
   ```

5. 将同一个值分别写入本机 `EMO_AGENT_PROXY_SECRET` 和 Sites hosted secret。不要把真实值发进聊天、文档或 Git。
6. 在 Sites 配置 `EMO_AGENT_ORIGIN=https://你的固定隧道域名`，不要使用会变化的临时 quick tunnel URL。Cloudflare Access 服务令牌准备完成后，还要配置 `CF_ACCESS_CLIENT_ID` 与 `CF_ACCESS_CLIENT_SECRET`。

## 接入真实 LLM 前的费用保护

1. API Key **只**填在本机 `Sites/.env.local` 的 `DEEPSEEK_API_KEY`，绝不填入 Sites secrets、前端代码或聊天消息。
2. 先保留 `.env.example` 中的默认用量限制。公开试用时建议不要提高 `EMO_AGENT_LLM_UPSTREAM_CALLS_PER_DAY=100`、`EMO_AGENT_LLM_UPSTREAM_CALLS_PER_USER_PER_DAY=20`、`DEEPSEEK_MAX_TOKENS=1000` 或 `DEEPSEEK_SUMMARY_MAX_TOKENS=1500`。
3. 在 DeepSeek 账户只充值你可以接受损失的小额预付余额，并开启可用的余额提醒。应用层配额可以限制本项目，账户余额才是 API Key 泄露或其他项目误用时的最终金额上限。
4. 联网搜索只使用同一个 `DEEPSEEK_API_KEY`，不再配置任何独立搜索服务的密钥。保留 `DEEPSEEK_ENABLE_WEB_SEARCH=true`，并将账户预付余额限制为你可以接受的金额。

## 每次开机启动

```powershell
.\Sites\start-local-backend.ps1 -Python "D:\Anaconda\envs\emotion-agent\python.exe"
cloudflared tunnel --config "C:\安全目录\emo-agent-cloudflared.yml" run
```

不要把 FastAPI 改为监听 `0.0.0.0`，不要在路由器上配置 7860 端口转发，也不要直接公开 Uvicorn 地址。

## 发布 Sites

1. 打开 ChatGPT Sites，选择 `Sites/hosted-site` 作为项目。
2. 在 Site Settings 添加 `EMO_AGENT_ORIGIN`、`EMO_AGENT_PROXY_SECRET`、`CF_ACCESS_CLIENT_ID` 与 `CF_ACCESS_CLIENT_SECRET`。
3. 先保存版本，不部署；检查代理实现没有把密钥编译进浏览器 bundle。
4. 测试未登录、登录、换浏览器、清 Cookie、伪造 `user_id`、超大上传、连续请求、删除其他会话等场景。
5. 确认后再部署，并把访问范围改为 `Anyone on the internet`。

## 验收命令

健康检查可直接访问，但只返回配置状态：

```powershell
Invoke-RestMethod https://你的隧道域名/api/health
```

无代理密钥的 API 必须返回 `401`：

```powershell
Invoke-WebRequest https://你的隧道域名/api/sessions -SkipHttpErrorCheck
```

携带密钥和代理身份的请求才应成功：

```powershell
$headers = @{
  "X-Emo-Proxy-Secret" = $env:EMO_AGENT_PROXY_SECRET
  "X-Emo-User-Id" = "manual-smoke-test"
}
Invoke-RestMethod https://你的隧道域名/api/sessions -Headers $headers
```

## 运营限制

- 当前 SQLite 适合少量试玩，不适合高并发。
- 为 DeepSeek 和搜索供应商设置消费上限与告警。
- 定期备份 `backend/data/*.sqlite3`，备份中包含用户对话和情绪数据，应加密保存。
- 明示这不是医疗诊断服务；不要收集病历、身份证、支付卡等敏感数据。
- 公布隐私说明、数据保留期限和删除方式。停止试玩时先将 Site 改为非公开，再停止 Tunnel。

## 官方依据

- Sites 可公开给互联网访客，并支持 hosted environment secrets。
- Sign in with ChatGPT 会把已认证身份提供给 Sites 服务端；授权判断应留在服务端。
- Sites 仍处于 public beta，功能、地区和套餐可用性及配额可能变化。

官方文档：https://learn.chatgpt.com/docs/sites
